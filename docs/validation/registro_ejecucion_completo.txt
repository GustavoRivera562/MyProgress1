2. INSPECCIÓN Y DIAGNÓSTICO
======================================================================

HomeScreenTest:
- Clase: com.example.myprogres.ui.HomeScreenTest.
- Asersiones originales preservadas:
  1) “¿Listo para entrenar?” visible.
  2) “500 ml” visible.
- La prueba corre bajo Robolectric y Compose UI test.
- El stack trace falla al lanzar androidx.activity.ComponentActivity desde ActivityScenarioRule.before.
- La falla ocurre antes de setContent y antes de las aserciones.
- Texto del fallo: Robolectric no puede resolver la actividad para el intent MAIN/LAUNCHER, con componente org.robolectric.default/androidx.activity.ComponentActivity.
- Se inspeccionaron versiones de AndroidX Activity Compose, Compose UI test, Robolectric y dependencias Gradle.
- Se probaron variantes temporales del manifiesto/declaración de Activity y de la dependencia de manifiesto Compose. No solucionaron el error y se restauraron los archivos al estado previo.
- No se cambió ninguna versión de dependencia.
- La prueba no se desactivó ni se eliminó. Continúa fallando.

Arquitectura y manejo de errores:
- ProgressViewModel ejecuta mutaciones locales con ErrorManager y pide sincronización después del éxito local.
- OfflineProgressRepository usa Room; no depende de Firestore para guardar localmente.
- SyncCoordinator consulta solo PENDING por UID, excluye ownerUid nulo y no sincroniza error_logs.
- SyncCoordinator escribe Workout antes de Sets y luego procesa hidratación.
- Usa FirebaseAuth.currentUser.uid, mutex para evitar concurrencia y verificaciones de sesión antes/después de escribir.
- El estado SYNCED se marca después del ACK remoto mediante actualizaciones DAO condicionales.
- Una falla remota evita marcar el registro SYNCED; debe permanecer PENDING si el CAS no se ejecuta.
- Los UUID locales se usan como IDs estables de documentos bajo users/{uid}.
- ErrorLogEntity no tiene campos de contraseña, token o correo; la tabla es local.

Configuración del emulador:
- Debug toma el host desde firestore-emulator.local.properties.
- Valor local leído: host=192.168.1.8.
- Hilt configura FirebaseFirestore.useEmulator(host, 8080) solo en Debug y falla explícitamente si falta host.
- Release no invoca useEmulator y tiene el host vacío.
- No se modificó configuración de producción.
